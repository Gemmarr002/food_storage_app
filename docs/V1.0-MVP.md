## 一、产品概述



### 1\.1 产品背景

面向家庭做饭人群，核心解决三大痛点：

1. 家里食材不知道怎么消耗，经常放坏浪费；

2. 不知道做什么菜，选择困难；

3. 有饮食忌口或食物过敏，选菜容易踩雷。

产品通过拍照识别录入食材清单，自动计算新鲜度并提醒临期；提供AI厨房问答助手；基于用户历史行为做个性化菜品推荐；全局过滤过敏与忌口食材，支持菜品收藏。



### 1\.2 目标用户

- 日常在家做饭的普通用户；

- 希望消耗冰箱现有食材、减少浪费的人群；

- 有饮食忌口或食物过敏的人群。

### 1\.3 MVP核心目标

1. 完成底部4标签页完整页面交互：食材清单 / AI助手问答 / 推荐 / 我的；

2. 食材库存管理：拍照识别录入 \+ 手动录入、新鲜度自动计算与展示、批量管理；

3. AI厨房问答助手，支持自由对话生成菜谱；

4. AI个性化菜品推荐、菜品收藏；

5. 「我的」页面维护忌口、过敏食材清单，**全局生效**：问答、推荐自动规避；

6. 数据持久化：食材库存、收藏菜谱、忌口过敏列表、历史交互全部存储飞书多维表格；

7. 约束：MVP为单用户Demo，不做账号体系；不存储用户实拍原图；全部LLM调用消耗个人API免费额度。

### 1\.4 MVP不做范围

1. 不做PWA / IndexedDB本地存储（规划为后续迭代）；

2. 不存储用户拍摄的原始照片，仅使用固定食材图标；

3. 不做多用户账号登录体系；

4. 不做支付、社区分享功能；

5. 不做RAG菜谱知识库（规划为后续迭代，用于降低幻觉）；

6. 不做工业级推荐算法（协同过滤、向量召回等），MVP采用LLM简易个性化分析。

### 1\.5 后续迭代规划

|迭代版本|核心内容|
|---|---|
|迭代1|接入对象存储OSS，支持保存、回看用户实拍食材原图|
|迭代2|接入菜谱RAG知识库，导入真实菜谱文档，通过检索召回真实菜谱，降低大模型幻觉|
|迭代3|自研前端，实现PWA \+ IndexedDB，数据存储在浏览器本地，去除飞书多维表格依赖，支持离线可用|
|迭代4|多设备数据同步、多用户账号体系|

## 三、各页面详细需求



### Tab1：食材清单 — 冰箱食材库存页



**页面定位**：展示全部已录入食材，支持快速筛选、单品查看、批量管理。



#### 3\.1\.1 页面元素

1. **顶部新鲜度筛选栏**

    - 筛选标签：全部 / 良好（绿）/ 一般（黄）/ 临近过期（灰）/ 已过期（红）

    - 默认选中「全部」；点击标签，下方食材区域仅展示对应新鲜度的食材。

2. **食材展示区：网格图标布局**

    - 卡片网格排布，以食材固定图标为主体视觉；

    - 新鲜度标识方式：**图标外框使用对应颜色边框**

        - 良好：绿色边框

        - 一般：黄色边框

        - 临近过期：灰色边框

        - 已过期：红色边框

    - 图标下方简洁文字：食材名称、数量（一人份、两人份、三人份、以此类推）已入库X天；

    - 视觉目标：信息密度高、直观清爽，适配手机端浏览。

3. **底部操作区**

    - 【拍照录入食材】按钮

    - 【手动录入食材】按钮

    - 【批量管理】按钮

4. **顶部弱提示（条件展示）**

    - 当存在已过期食材时，页面顶部小字提示：「存在已过期食材，请及时清理」

#### 3\.1\.2 交互规则

1. **单击食材图标** → 跳转【食材单品详情页】；

2. **长按食材图标** → 弹出操作浮窗，选项：

    - 编辑食材（修改食材名称、调整入库时间、修改库存数量）

    - 删除单条食材

3. **点击【批量管理】** → 进入多选模式

    - 食材图标出现勾选框，可多选；

    - 底部出现【批量删除】按钮；

    - 支持【退出批量模式】返回正常浏览。

#### 3\.1\.3 食材单品详情页（单击进入）

页面内容：

- 食材大图（固定图标放大展示）

- 食材名称

- 剩余数量（几人份）

- 入库时间 / 已存放天数

- 新鲜度标签（颜色标识）

- 「用这个食材能做什么」推荐区：

    - 调用LLM，仅基于该食材 \+ 全局忌口过敏约束，推荐3\-5道菜品；

    - 每道菜展示菜名、简要步骤；

    - 支持点击收藏。

#### 3\.1\.4 业务逻辑

1. 打开页面，Dify读取飞书多维表格【食材库存表】，拿到全部记录；

2. 读取内置静态保质期配置表，代码节点计算：已存放天数、剩余保质期、新鲜度标签；

3. 顶部筛选为前端本地过滤，不触发新的LLM调用；

4. 拍照录入流程：拍照上传 → VL识别食材名称 → 匹配固定图标URL → 用户确认编辑 → 写入库存表；实拍图片识别完成即丢弃；

5. 手动录入：用户填写食材名称，系统自动记录当前时间为入库时间，匹配对应图标，写入库存表；

6. 用户长按修改入库时间后，新鲜度标签同步重新计算；

7. 删除 / 批量删除：删除飞书多维表格对应行记录。

### Tab2：AI助手问答 — 厨房小帮手对话页



**页面定位**：自由对话式厨房助手，用户可提问做菜相关问题、生成菜谱；全局带入过敏 \& 忌口过滤规则。



#### 3\.2\.1 页面元素

1. 对话聊天窗口，展示历史对话记录（气泡形式）；

2. 底部输入框，支持用户自由输入问题；

3. 发送按钮；

4. AI回复的菜谱卡片右上角提供【收藏】按钮。

#### 3\.2\.2 核心业务规则【忌口 \& 过敏全局生效】

1. 每次调用LLM时，**自动读取飞书多维表格【用户设置表】中的过敏 \& 忌口清单，拼接进System Prompt**；

2. 强制约束AI：

    - 过敏食材：严禁出现在任何菜谱中，完全不能使用；

    - 忌口不吃食材：尽量避免使用，如菜品不可避免用到，必须提供可行的替代食材方案；

3. 用户提问场景：

    - 场景A：用户提到家里食材 → 同时带入当前冰箱库存食材，优先消耗库存；

    - 场景B：用户未提食材 → 按用户描述条件生成菜谱；

4. 用户点击【收藏】→ 菜谱信息写入【收藏菜谱表】。

#### 3\.2\.3 异常状态

- AI加载中：展示loading动画；

- 调用失败：提示「网络异常，请稍后重试」。

### Tab3：推荐 — AI个性化菜品推荐页



**页面定位**：基于用户历史问答、收藏行为、口味偏好做个性化菜谱推荐；自动过滤过敏、忌口食材；支持收藏。



#### 3\.3\.1 页面元素

1. 顶部标题：「为你推荐」；

2. 右上角【刷新推荐】按钮；

3. 推荐菜谱卡片流；

    - 每张卡片：菜名、简要介绍、烹饪时长、【收藏】按钮；

    - 点击卡片展开完整菜谱详情；

4. 收藏状态：未收藏 / 已收藏（图标填充变化）。

#### 3\.3\.2 AI推荐逻辑（MVP Demo级方案）

1. Dify读取以下数据源：

    - 用户历史问答记录（来自【用户历史交互表】）；

    - 用户收藏过的菜谱（来自【收藏菜谱表】）；

    - 用户冰箱高频出现的食材（来自【食材库存表】）；

    - 用户过敏 \& 忌口食材清单（来自【用户设置表】）；

2. 将以上全部信息交给LLM，由AI分析用户口味偏好，输出5\-8道个性化推荐菜谱；

3. **强制过滤规则**：

    - 所有推荐结果自动剔除含有过敏食材的菜品；

    - 忌口不吃的食材尽量规避，不可避免时给出替代方案；

4. 触发时机：

    - 用户首次进入推荐Tab时触发一次AI调用；

    - 用户点击【刷新推荐】按钮重新生成。

#### 3\.3\.3 边界说明

- MVP不使用协同过滤、向量召回等工业级推荐算法，采用大模型理解用户历史行为做简易个性化推荐；

- 结果存在一定随机性，属于Demo级方案，后续迭代引入向量知识库做真正召回式推荐。

### Tab4：我的 — 个人设置页



**页面定位**：集中管理收藏菜谱与饮食设置。



#### 3\.4\.1 模块一：我的收藏夹

1. 展示所有从【AI问答】、【推荐页】收藏的菜谱卡片列表；

2. 点击卡片查看完整菜谱详情；

3. 单条支持取消收藏（删除【收藏菜谱表】对应记录）；

4. 空状态：暂无收藏菜品，引导去推荐页或问答页发现菜品。

#### 3\.4\.2 模块二：饮食设置

两个可编辑列表：



|列表|规则级别|说明|
|---|---|---|
|🚫 过敏食材|强约束（严禁使用）|用户手动添加、删除；全局强拦截，问答、推荐均不能出现|
|⚠ 不吃 / 忌口食材|软约束（尽量规避，必要提供替代）|用户手动添加、删除；尽量避免，实在无法避免输出替代方案|



用户保存后，写入飞书多维表格【用户设置表】；后续每一次LLM调用都会读取这份配置传给大模型。

## 五、静态配置



### 5\.1 食材\-图标映射表（Dify代码节点内置JSON）



```JSON
{
  "鸡蛋": "https://xxx/egg.png",
  "番茄": "https://xxx/tomato.png",
  "土豆": "https://xxx/potato.png",
  "默认": "https://xxx/default_food.png"
}
```



逻辑：识别出食材名称，匹配对应URL；未收录食材使用默认图标。



### 5\.2 食材\-冰箱保质期配置表（Dify代码节点内置）



|食材|冰箱标准保质期（天）|
|---|---|
|鸡蛋|14|
|番茄|7|
|土豆|20|
|默认|5|



### 5\.3 新鲜度计算规则



```Plain Text
已存放天数 = 当前时间 − 入库时间
剩余天数 = 标准保质期 − 已存放天数

- 剩余 > 5天：良好（绿色边框）
- 2 ≤ 剩余 ≤ 5天：一般（黄色边框）
- 0 < 剩余 < 2天：临近过期（橙红色边框）
- 剩余 ≤ 0天：已过期（灰色边框）
```

## 六、关键业务流程



### 6\.1 拍照录入食材流程



```Plain Text
graph TD
    A[用户拍照上传食材照片] --> B[Dify接收图片]
    B --> C[调用VL多模态模型识别]
    C --> D[输出食材名称数组]
    D --> E[代码节点查表匹配固定图标URL]
    E --> F[弹出识别结果确认页]
    F --> G{用户确认/编辑}
    G -->|确认入库| H[写入食材库存表：名称+入库时间+图标URL]
    G -->|修改后确认| H
    H --> I[实拍图片生命周期结束，丢弃]
```



### 6\.2 忌口 \& 过敏全局生效链路



```Plain Text
graph TD
    A[用户在我的页面维护过敏/忌口清单] --> B[保存写入用户设置表]
    C[触发LLM调用：问答/推荐/单品详情] --> D[Dify读取用户设置表]
    D --> E[将过敏/忌口清单拼接到System Prompt]
    E --> F[大模型接收约束生成菜谱]
    F --> G[过敏食材完全禁止 / 忌口尽量规避必要给替代]
    G --> H[输出结果到前端页面展示]
```



### 6\.3 新鲜度自动计算流程



```Plain Text
graph TD
    A[打开食材来源页] --> B[Dify读取食材库存表]
    B --> C[读取静态保质期配置表]
    C --> D[代码节点计算：当前时间 - 入库时间 = 已存放天数]
    D --> E[匹配保质期 → 得出剩余天数]
    E --> F[按规则打上新鲜度标签]
    F --> G[前端渲染：图标边框颜色 + 已入库天数文字]
```

## 七、AI相关Prompt汇总



### 7\.1 VL视觉识别Prompt（仅识别食材名）



```Plain Text
你是食材识别助手，识别图片里面出现的食材。
只输出JSON数组，数组内为食材名称，不要输出保质期、新鲜度、数量等额外信息。
如果识别不到食材，返回空数组[]。
输出示例：["鸡蛋","番茄"]
不要多余解释，只返回JSON。
```



### 7\.2 菜谱生成 System Prompt（含忌口约束）



```Plain Text
你是家庭厨房菜谱助手。
输入会包含两部分信息：
1.家中现有食材列表，可以为空；
2.筛选条件：口味、烹饪难度。

规则：
1. 如果用户传入家中食材，则优先利用已有食材生成菜品；
2. 如果用户没有传入食材，仅传入口味、难度条件，则直接生成满足口味难度的菜谱，不需要参考食材；
3. 每次输出3-5道家常菜；输出包含菜名、所需全部食材、烹饪时长、步骤；
4. 不要输出宴席大菜，输出普通人家庭可实现菜品。
5. 输出格式清晰，便于前端展示。

重要饮食约束：
用户提供了过敏食材清单和不吃的忌口食材清单。
1.过敏食材：严禁出现在任何菜谱中，完全不能使用；
2.忌口不吃食材：尽量避免使用，如果菜品不可避免用到该食材，必须提供可行的替代食材方案；
生成所有菜谱必须遵守以上约束。
```



### 7\.3 单品食材推荐Prompt（Tab1单品详情页用）



```Plain Text
用户当前查看的食材是：{食材名称}。
请基于这一种主要食材，推荐3-5道家常菜。
优先使用该食材为主料，辅料尽量使用常见家庭常备调料。
输出包含：菜名、所需食材、烹饪时长、步骤。
严格遵守用户的过敏与忌口约束。
```

## 八、非功能需求



### 8\.1 性能

- 页面首屏加载 ≤ 3秒（移动端4G环境）；

- LLM调用首字响应 ≤ 5秒；

- 食材列表加载 ≤ 2秒（50条以内数据）。

### 8\.2 兼容性

- 支持主流移动端浏览器（Safari、Chrome、微信内置浏览器）；

- 支持PC端浏览器访问Demo；

- 手机浏览器支持「添加到主屏幕」快捷方式。

### 8\.3 安全

- API Key仅保存在Dify后台，绝不暴露到前端；

- Dify发布网页开启访问密码，防止未授权调用消耗额度；

- 大模型平台设置每日/总消耗硬上限 \+ 告警，防止超额账单。

### 8\.4 数据持久化

- 食材库存、收藏、用户设置、历史交互全部持久化存储飞书多维表格；

- 关闭网页、刷新页面，数据不丢失。

## 九、风险与限制



|风险类别|具体描述|应对方案|
|---|---|---|
|AI幻觉\-菜谱|大模型生成的菜谱可能存在步骤错误、食材搭配不合理|MVP标注为AI生成，仅供参考；后续迭代接入RAG真实菜谱知识库|
|AI幻觉\-忌口|Prompt软约束极端情况下可能失效，AI仍输出禁忌食材|MVP为Prompt层约束；后续迭代增加代码关键词校验，检测输出菜谱是否命中过敏食材，做二次拦截|
|图片识别误差|光线差、遮挡、堆叠导致VL识别漏检、错检|识别结果必须经过用户确认页，支持手动增删修改；保留手动录入作为兜底|
|新鲜度准确性|保质期为静态参考值，实际受储存条件影响|页面标注「新鲜度仅供参考」；支持用户长按手动调整入库时间修正|
|API额度风险|全部访问消耗个人API免费额度，链接泄露可能被刷|①平台设置硬消耗上限；②Dify开启访问密码；③页面提示仅供演示，请勿高频调用|
|数据存储依赖|MVP依赖飞书多维表格，飞书服务异常影响使用|MVP可接受；迭代3规划IndexedDB本地存储去除依赖|
|推荐随机性|LLM生成的个性化推荐结果不稳定，非工业级|MVP明确为Demo方案；后续迭代引入向量召回\+真实菜谱库|
|单用户限制|MVP无账号体系，所有访问者操作同一份数据|作品集Demo可接受；迭代4规划多用户账号体系|
