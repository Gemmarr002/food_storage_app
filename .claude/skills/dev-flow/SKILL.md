# 开发流程（dev-flow）

## 何时使用

开始一个新功能或一次迭代，需要从需求文档推进到可运行、已验证的代码时。作为总入口，按需调度其他技能。

## 流程（单人 7–10 天交付）

1. **明确需求**：读 `docs/V1.2_MVP.md` 及相关设计文档，确定功能范围。记住 V1.2 原则：**不做 AI、本地优先、不依赖网络**。
2. **拆任务**：把功能拆成小步骤，用 `TaskCreate` 建任务清单，按序推进。
3. **数据先行**：先定数据模型与持久化，用 `data` 技能。
4. **实现**：前端页面 / 组件用 `frontend` 技能；需要服务端能力时用 `backend` 技能。
5. **测试**：为核心逻辑补测试，用 `testing` 技能。
6. **验证**：`cd frontend && pnpm dev`，在浏览器 390px 视口下走一遍完整用户路径。
7. **交付记录**：更新 `docs/` 中对应版本说明或变更记录。

## 原则

- **本地优先**：不引入 AI / 网络依赖，除非需求明确要求。
- **小步可运行**：每一步都能跑起来，避免一次性大改导致不可调试。
- **复用优先**：优先用 shadcn 组件、现有工具函数，不重复造轮子。

## 验收

- 功能可运行、数据刷新后不丢、关键逻辑有测试、文档同步更新。
